# Fe 26.5 benchmark migration

The checked-in Fe implementations target Fe 26.5.0 (`3dab95f8e`). The
release changes the language and stdlib incompatibly, so the sources no
longer compile with 26.4.1.

## Source changes

- Mutable bindings use `var x = …`; `let mut` is rejected. This also applies
  to the generated scale-family templates.
- `Address.inner` is private to std. Addresses stay typed end to end
  (`crypto::create2_address`, `clones::clone_initcode` and events take and
  return `Address`). Words are read with `.word()`, and Curve's packed oracle
  word is decoded with `Address::from_word_truncate`. Factory orders tokens
  with `Address`'s `Ord`.
- ETH amounts and timestamps are typed. The vault converts with
  `ctx.value().as_wei()`, `wei(amount)` and `ctx.selfbalance().as_wei()`;
  `create2_raw` takes `Wei::zero()`. Pair, Yearn and Curve keep their stored
  timestamps as `u256` via `ctx.timestamp().as_seconds()`.
- `RawMem` is gone, and with it the `raw` effect. Curve reads the oracle
  return word with `MemBuffer::read_word(0)`.
- `StorageBytes` lost its salt parameters, so Factory and Yearn V2 use
  `StorageBytes<u256>`. This resolves the nested-salt workaround from the
  26.4.1 port. `Bytes::view()` is replaced by `payload_span()`.
- The ABI-encoded `std::abi::MemVec` is removed. Curve's scratch arrays are
  `MemArray<u256>` (`new_zeroed`, indexing), encoded for events and returns
  with `DynArray::from_slice`. Collection lengths and indices are `usize`, so
  the `u256` coin indices are cast at each array access and ABI array lengths
  are cast back with `as u256`.

## Validation

Validated on 2026-10-26 with the Fe 26.5.0 release binary resolved by the
default toolchain resolver at `-O 2` and solc 0.8.38 via IR with 200 optimizer
runs on the shared Prague EVM target:

```sh
cargo run --release -- run \
  --profile fe-latest-O2 --profile solc-latest-viair-runs200 --no-cache
```

The run compiled 127 artifacts with zero failures. All 457 scenario rows
passed, including all 206 Fe rows and their Fe/Solidity differential checks.
`scripts/test-fe-parity.py` passes, and so do the bench-cli tests.

## Compared with 26.4.1

Compared with the 2026-10-01 26.4.1 run over the same 206 Fe rows:

- Total measured gas is 0.8% lower. Benchmarks whose sources only changed
  `let mut` to `var` show compiler gains: loops are 10–20% cheaper
  (`loop_bound`), external-call loops about 6% (`external_calls`) and
  `merkle_verifier` 7%. Dispatch, ABI-argument, storage-slot and mapping
  families are unchanged.
- Runtime code is much smaller for the real-derived ports: Curve 30,983 →
  19,217 bytes (−38%), Pair 8,470 → 5,961 (−30%), Yearn V2 18,089 → 14,005
  (−23%) and Factory 1,267 → 1,156 (−9%). Their gas falls 0.2–2.3%.
- Compiling all Fe artifacts takes about 33 s instead of about 23 minutes.
  `scale_mapping_depth_64` drops from about 18 minutes to under a second, and
  peak compiler memory falls from about 12 GiB to 2.6 GiB.
