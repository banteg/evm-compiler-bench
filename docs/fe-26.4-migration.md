# Fe 26.4.1 benchmark migration

Superseded by the [Fe 26.5 migration](fe-26.5-migration.md); the
sources no longer compile with 26.4.1.

The checked-in Fe implementations target Fe 26.4.1 (`dbb291dbc`). This
migration moves the suite directly from Fe 26.2 to 26.4.1, adds Fe ports of
four real-derived benchmarks, and pairs every Fe artifact with Solidity in the
behavior lane. The sources track the current Fe release; older compiler
versions are not guaranteed to compile them.

## New ports

Uniswap V2 Factory/Pair, Yearn V2 and Curve StableSwap now have Fe
implementations. Yearn V3 remains the only benchmark without one and is skipped
for Fe profiles.

- Factory initcode and Yearn metadata use `StorageBytes::store_view` and
  `to_memory`. Factory salts use `keccak_packed`; permits use
  `crypto::eip712_digest`. Yearn default names/symbols and Curve ERC-1271
  signatures use packed encoding.
- Yearn `StrategyReported` and the three Curve liquidity events use `#[event]`.
- Curve scratch arrays use `MemVec<u256>`. `copy_array` allocates independent
  buffers so fee calculations cannot mutate the original balances. ABI arrays
  use typed `get` access, including constructor addresses.
- External views use `Address::static`. ERC-20 transfers use
  `erc20::try_transfer` and `try_transfer_from`, accepting `Ok` and `NoCode`
  and reverting with each reference's error string otherwise. This keeps the
  references' optional-return handling, including success for an empty return
  from an account without code. Stdlib `safe_transfer` would instead reject
  accounts without code and bubble token reverts.
- Permits use `crypto::ecrecover_raw`, which accepts the same signatures as
  Solidity's `ecrecover` builtin. The default `crypto::ecrecover` rejects
  non-canonical (high-s) signatures that the references accept.
- Pair minting uses `core::num::isqrt`. This changes the square-root algorithm
  from the Solidity reference's Babylonian loop to fixed Newton iterations,
  while retaining the floor-square-root result.

Nested `StorageBytes` still needs explicit salts in the released compiler.
Factory and Yearn V2 use `StorageBytes<u256, 0, 1>` so they compile with
unmodified 26.4.1; Fe reserves these salts before assigning the other maps'
inferred salts. See [Compiler fixes](#compiler-fixes).

## Existing benchmarks

- CREATE2 address calculation uses `crypto::create2_address`.
- EIP-1167 initcode hashing uses `clones::clone_initcode` and
  `crypto::keccak256` instead of handwritten bytecode and memory writes.
- Fixed-word permit and salt hashes use `crypto::keccak_words`.
- Merkle verification uses `merkle::verify` and `merkle::hash_pair_sorted`.
- Vault deposits declare and return `u256`, including in the generated ABI.
  Withdrawals use `call.send_value` and preserve the existing failure behavior.

## Differential checks

Each selected Fe artifact forms a behavior pair with the preferred selected solc
artifact for the same benchmark (`comparison_pairs`). The behavior lane runs the
pair's scenario differential tests and applicable randomized/property checks,
comparing success, successful return data when enabled, normalized observers,
and logs for benchmarks supported by the log-normalization harness. As for the
other verified compiler pairs, evidence is cached by bytecode, scenario, harness
source and Foundry version, never by gas cache hits, and a mismatch fails the
run. Fe rows record the result in `baseline_differential_check` and
`behavior_pairs`; without a selected solc counterpart they show `not_run`.
Revert payloads are not compared.

`scripts/test-fe-parity.py` exercises a passing run, a fully cached run, and a
mutated Pair mint (`+1` LP token) that must fail its differential check. Run it
with `python3` after building the release CLI. It runs with `--offline`, which
resolves solc and Vyper only through `EVM_BENCH_SOLC`/`EVM_BENCH_VYPER` or
`PATH`, so set those along with `EVM_BENCH_FE` when needed.

The shared scenarios add coverage for a false-returning Pair token, Yearn
metadata crossing a storage-word boundary, and a signed Yearn permit and
rejection of its replay. The long metadata fixture respects Vyper's 64-byte
name and 32-byte symbol bounds.

## Validation

Validated on 2026-10-01 with the unmodified Fe 26.4.1 release at `-O 2`,
Solidity 0.8.36 via IR with 200 optimizer runs, and the shared Prague EVM target:

```sh
EVM_BENCH_FE=/path/to/fe-26.4.1 cargo run --release -- run \
  --profile fe-latest-O2 --profile solc-latest-viair-runs200 --no-cache
```

The complete run compiled 127 artifacts with zero failures: 63 Fe and 64
Solidity implementations. All 457 scenario rows passed, including all 206 Fe
rows and their Fe/Solidity differential checks. Fe coverage comprises 14 fixed
implementations (116 scenarios) and all 49 generated implementations (90
scenarios), across seven scale families at N = 1, 2, 4, 8, 16, 32 and 64.

Compilation of `scale_mapping_depth_64` remains expensive, taking roughly 18
minutes. It completes successfully; the scale range was not reduced.

## Compiler fixes

Two fixes found during this migration are on branches of `argotorg/fe`, both
starting from the 26.4.1 release with regression tests and a newsfragment:

| Branch | Fix |
| --- | --- |
| `fix/nested-storage-bytes-layout` | Distinguish inferred length/data salts for nested `StorageBytes`. |
| `fix/layout-template-root-use-accounting` | Avoid counting diagnostic copies of const terms as additional layout-root occurrences. |

With the first fix, Factory and Yearn V2 compile without explicit salts. The
release-compatible benchmark sources keep the salts until the fix is released.
The second issue was found while checking the first fix against the existing
compiler suite: unmodified 26.4.1 hits an internal assertion, while the fixed
compiler reports the intended non-regular recursive provider diagnostic.
