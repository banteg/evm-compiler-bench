# EVM Compiler Bench v4: Solar

Solar joins solc, solx, Vyper, and Fe. The matrix now contains 127 profiles over
64 benchmarks. Solar is pinned at
`716e9cbcde88165f931173f1c1fda852ed63afa0`; its package version remains 0.2.0,
but this source revision is newer than the published v0.2.0 release.

The two Solar profiles use Standard JSON optimizer enabled with runs 200
(gas) or runs 1 (size), one compiler worker, Prague, and metadata disabled.
Their comparison baseline is pinned solc 0.8.36 viaIR / runs 200 on identical
materialized Solidity sources. Solar has its own Rust frontend and EVM backend.

## Results

Across all 64 benchmarks and 247 matched scenarios per mode, geometric-mean
deltas relative to solc 0.8.36 viaIR / runs 200 are:

| Solar profile | Runtime gas | Runtime bytecode | Scenario deployment gas |
| --- | ---: | ---: | ---: |
| Gas / runs 200 | −8.2% | −25.9% | −16.8% |
| Size / runs 1 | −2.7% | −26.6% | −17.2% |

The site's headline cards use the fixed and scale suites: 59 artifacts and
129 scenarios. On that narrower population, Solar gas uses 9.6% less runtime
gas and 26.6% less runtime bytecode. The default comparison includes the
real-derived suite as well. Size mode can increase both gas and bytecode for
individual workloads; the report preserves those regressions.

Bytecode statistics count each artifact once. Gas and deployment statistics
count each matched scenario/access/deployment unit once. Expected reverts remain
in the scenario population. All Solar profiles compile and pass their measured
behavior checks; no Solar runtime rows are excluded.

The main matrix stores one compiler-process timing sample per artifact by
default. This host builds Solar as x86-64; the solc executable is universal.
The standard runner does not force a common architecture. Those compilation
timings include the recorded host and binary choices. The
[spike](../spikes/solar-716e9cbc/README.md) separately
contains five-process medians on five selected contracts with both compilers
explicitly run as x86-64. Neither is a whole-project parallel build benchmark.

## Verification and reproducibility

The full matrix produces 7,827 artifacts, 296 compile failures, and 29,367 gas
measurements. Both Solar profiles compile all 64 benchmarks. The three added
solc legacy failures are ABI arity 16, 32, and 64 stack-too-deep errors.

All 128 Solar/solc pairs have identical complete materialized source bundles
and ABI entries (ignoring only top-level ABI entry order). Every pair passes
scenario differential checks: 494 Solar scenarios total. The applicable ten
randomized checks and ten property checks also pass. The complete matrix records
320 verified compiler pairs.

All 253 compiled artifacts from the spike reproduce their source hash and
creation/runtime bytecode hashes. Gas measurements differ because the spike
used solc 0.8.36 to compile the measurement harness and fixtures, while the main
matrix uses solc 0.8.34. Optimized harness overhead also depends on the complete
generated shard context.
The release audit records those measurement offsets separately from the exact
compiled-contract identity. The integrated values above use the full main matrix;
they are internal-call harness measurements, including wrapper and fixture costs.
In the spike comparison, 231 scenarios reproduce each profile's spike gas exactly.
Two scenarios have a common 11-gas offset, and fourteen have profile-dependent
harness offsets. These are recorded in the audit rather than attributed to changes
in the compiled benchmark bytecode.

The integration exposed and fixed a reproducibility gap: Foundry previously
auto-selected the harness compiler, and its configuration was missing from gas
and behavior cache keys. The harness now pins solc 0.8.34; effective Foundry
configuration is hashed into both caches. Public compiler/EVM settings and the
configuration hash are recorded without unrelated account configuration.

Gas keys additionally include the exact generated shard source. Cache hits no
longer prune tests or repack artifacts: a missing entry reruns its original complete
shard, and refreshed rows replace cached siblings. A partial-cache regression test
removed one of twenty entries; the intact shard regenerated twenty identical unique
measurements with the same source hash. The run manifest lists each shard's source
hash and artifact membership. All measurements and behavior checks were refreshed.

The same 13 historical compiler/benchmark artifacts retain observed runtime
failures from v3. They remain visible in the reliability panel and are excluded
from performance comparisons. All raw measurements remain available.

The resolver fetches the exact Solar commit, requires a clean checkout, and
builds with Rust 1.96.0 and locked dependencies. It records the Rust host target,
lockfile hash, build flags, binary SHA-256, full revision, and Solidity compatibility
version separately, and checks cached binaries against their build receipt.

Run `uv run scripts/verify_solar_release.py` after a full benchmark run to verify
coverage, source and ABI equality, behavior evidence, spike bytecode identity,
harness offsets, and aggregate results. The audit writes
`target/solar-release-audit.json`.

Validation: 47 Rust tests, strict Clippy, five frontend tests, publication-policy
tests, schema/data validation, full Foundry run, and desktop/mobile report QA.
The report adds Solar presets, revision-aware selection, scale curves, and v4
social metadata with a new image URL. Reliability labels retain compiler names;
the movers panel now reports actual displayed increases and decreases.
