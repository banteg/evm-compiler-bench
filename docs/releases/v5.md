# EVM Compiler Bench v5: isolated transactions

Each measured call now runs as its own transaction. Reentrancy locks are
transient in every language where the Vyper reference uses `@nonreentrant`.
The matrix adds solc 0.8.38, Fe 26.5.0, and Solar at
`cb38e98632eebdf6c5bb60a792b83320c1312b28`. It keeps 127 profiles over
64 benchmarks.

Published run `20261028T181150Z` measures commit `80ee638` (tag `v0.5.0`) on
linux x86-64, Prague.

## Measurement changes

- Foundry runs with `--isolate`. Each measured call is a separate transaction,
  so warm-slot and transient-storage state no longer leaks from setup into the
  measured call.
- Solidity and Fe ports of Yearn V2, Yearn V3, and Curve use transient
  reentrancy locks. Compilers without transient storage (solc < 0.8.28 or a
  pre-Cancun target) compile the same declaration as storage, as Vyper does.
  Nonzero sentinels avoid a zero-slot write after first use. On the latest
  compilers this saves about 22k gas per locked Curve call and about 4.8k per
  locked Yearn call (21.9k on first use); Vyper results are unchanged.
- The Vyper Uniswap pair uses unchecked subtraction where the upstream pair does.
- Solar moves to `cb38e986` (Solidity 0.8.38 compatibility). It is built with
  the Rust version its workspace declares and compared with matched solc 0.8.38
  profiles.
- The harness compiles without CBOR metadata, so fixture creation code and the
  CREATE2 addresses it logs do not depend on the generated shard. Log hashes are
  compared for every benchmark.

v5 figures are not directly comparable with v4: the measurement scope,
baselines, and several sources changed.

## Verification

The full matrix produces 7,849 artifacts, 278 compile failures, and 35,533 gas
measurements; validation covers 35,811 result rows. 35,513 scenario checks pass.
The 20 unexpected outcomes are the known ones: time-advanced Curve oracle and
ramp scenarios under Vyper 0.4.0 Venom, and solc 0.4.26's draft CREATE2 opcode
in the Uniswap factory. All 383 compiler behavior pairs were re-verified; every
Solar profile compiles all 64 benchmarks and passes its behavior checks.

The first v5 run (`8138def`) failed `log_check` for Uniswap factory pair
creation on five Vyper 0.5.0b1 profiles. The fixture's shard-dependent metadata
changed the logged pair address; the harness fix above removed those failures
without changing any compiled benchmark bytecode.
